# Инструкция агенту

## Назначение и границы

Vue SPA для управления HH Clicker; backend остаётся источником истины.

## Карта кода

- `src/pages` — экраны; `src/components/ui` — общие примитивы.
- `src/api/contracts`, `src/services` — контракты и доступ к данным.
- `src/mocks`, `src/app/runtime.ts` — синтетические режимы; `src/styles/tokens.css` — UI-токены.
- `tests` — автономные проверки UI-логики.

## Инварианты

- Изменение API одновременно отражай в контрактах, реальной ветке сервиса и моках.
- Моки должны соблюдать те же допустимые состояния и переходы, что и backend.
- Реальные отклики требуют явного подтверждения пользователя.
- Наличие credentials и доступность HTTP не доказывают авторизацию.
- Не создавай второй долгоживущий доменный store; локально храни ввод и состояние экрана.
- Используй дизайн-токены и существующие UI-примитивы; не дублируй стили.
- Production использует API; query-параметр сценария не должен включать моки в сборке.

## Изменения и документация

Изменённый контракт одновременно отражай в клиентах, конфигурации, тестах и документации.
Проверяй утверждения по реализации. Не сохраняй планы, историю обсуждений и результаты
конкретных прогонов в постоянных инструкциях. Действующие причины решений описывай в архитектуре.

## Проверка

```powershell
npm.cmd run type-check
npm.cmd run build
node --test tests/*.test.mjs
```

Команды запуска сервисов и живые проверки не являются автономными тестами.
Условия интеграционных и ручных проверок смотри в документации.
