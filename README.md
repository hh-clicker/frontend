# HH Clicker Frontend

Веб-интерфейс локального HH Clicker на Vue 3, TypeScript и Vite. Интерфейс работает в
двух режимах: с моковыми данными для быстрой разработки UI и с настоящим backend API.

При включённом AI пустое резервное письмо запрещает отправку без сгенерированного текста.
Обычная ошибка генерации может использовать непустой резерв; лимит Codex требует отдельной
паузы и явного разрешения продолжить с резервным письмом для оставшегося запуска.

На странице «Резюме» можно повторно загрузить текст с HH, сохранив остальные настройки.
Страница «Браузер» содержит диагностику чтения HH и явную ИИ-починку; из ошибок поиска,
импорта и обработки вакансий можно перейти к проблемной вкладке без полной повторной диагностики.
Проверка доступна без Codex, ИИ-починка требует готового Generation Agent.

Установка готовых пакетов Windows, Linux и macOS и пользовательские сценарии описаны в
[общем руководстве](https://github.com/hh-clicker/.github/blob/master/profile/README.md).

## Запуск

```powershell
npm.cmd ci
npm.cmd run dev
```

`npm.cmd run dev` запускает mock-режим. Для интеграции с локальным backend:

```powershell
npm.cmd run dev:api
```

## Проверка

```powershell
npm.cmd run type-check
npm.cmd run build
node --test tests/*.test.mjs
```

Основные страницы находятся в `src/pages`, API-контракты — в `src/api/contracts`,
доступ к данным и бизнес-сценарии UI — в `src/services`, моковые данные — в `src/mocks`.

Оценка вакансий в API-режиме использует единый параллельный запуск на backend: партии
до 10 вакансий выполняются независимо. UI опрашивает общий прогресс и восстанавливает
активный запуск после обновления страницы. Разбиение и ограничение размера описаний
находятся на backend; запросов к HH этот сценарий не делает.

Архитектурные правила описаны в [ARCHITECTURE.md](ARCHITECTURE.md), настройка браузерных
уведомлений — в [NOTIFICATIONS.md](NOTIFICATIONS.md), инструкция для coding agents — в
[AGENTS.md](AGENTS.md).

Моки, сценарии и работа с настоящим API описаны в [TESTING.md](TESTING.md).
