# Архитектура frontend HH Clicker

## Поток данных

`src/app/runtime.ts` выбирает `mock` или `api`. Страница вызывает функцию из `src/services`;
сервис либо работает с `src/mocks`, либо отправляет запрос через `src/api/client.ts`.
Публичная форма данных определяется типами из `src/api/contracts` в обеих ветках.

```text
page/component → service → api client → backend
                       ↘ mock state
```

Компоненты не обращаются к backend в обход `services`. Исключение для чистой UI-логики
не требуется: её размещают в `utils`, `composables` или рядом с предметным компонентом.

## Уровни компонентов

- `pages` отвечают за загрузку данных, состояние конкретного экрана и композицию блоков.
- `components/ui` содержат общие примитивы без знания предметной области: кнопки, поля,
  alert, badge, dialog, skeleton и empty state.
- Общий `AppDialog` закрывается по подложке только при нажатии и отпускании указателя
  на самой подложке; выделение текста с отпусканием снаружи не закрывает диалог.
  Такая же проверка действует для выдвижной панели деталей стоп-листа.
- `components/<feature>` содержат переиспользуемые блоки предметной области и могут
  использовать `components/ui`.
- `components/navigation/AppShell.vue` владеет общей оболочкой, навигацией и селекторами.

Повторяемую разметку и поведение не копируют между страницами. При этом одноразовый
фрагмент не выносится в компонент только ради уменьшения размера файла: граница должна
иметь понятный интерфейс или повторное использование.

## Стили

Глобальные стили импортируются в определённом порядке из `src/main.ts`:

1. `tokens.css` — цвета, типографика, spacing, radii, размеры layout и shadows.
2. `base.css` — reset и базовые HTML-правила.
3. `buttons.css`, `forms.css`, `components.css`, `layout.css` — общие примитивы.
4. Файлы конкретных страниц и областей.

Новый общий цвет, размер, отступ, радиус или тень сначала добавляется осмысленной
CSS variable в `tokens.css`. Компоненты используют `var(--...)`; локальные значения
допустимы только для действительно уникальной геометрии или оттенка. Общие классы
принадлежат общему файлу стилей, страничные — файлу соответствующей области.

Scoped-стили допустимы для полностью локального компонента. Общий компонент не должен
зависеть от класса страницы, чтобы выглядеть корректно.

## Маршруты и состояние

Маршруты объявлены только в `src/app/router.ts` и загружают страницы лениво внутри
`AppShell`. После навигации router прокручивает страницу вверх. Старый `/attention`
перенаправляется на `/applications`.

`/market-analysis` показывает сохранённые запуски анализа для выбранного резюме. API-режим
использует `/api/v1/market-analyses`. Кнопка в шапке открывает диалог с полем размера выборки
от 0 до доступного максимума (по умолчанию все), селектом сохранённого поиска
и фильтром оценки вакансий: цель, смежная, проверить, мимо или все, включая без оценки.
Ноль не допускает запуск. Диалог
показывает размер выборки последних N вакансий с текстом и дату самого раннего сохранённого текста,
опрашивает историю во время расчёта и скачивает
готовый MD по отдельному endpoint. В mock-режиме используются только явно
демонстрационные данные. Текущий запуск извлекает дословные технологии, навыки и домены;
после первой завершённой партии показывает приблизительный остаток времени из API;
для работающего и упавшего запуска показывает прогресс-бар, а ошибку извлечения
можно продолжить с сохранённой позиции кнопкой в карточке запуска. Ручная остановка
дожидается результатов всех уже выданных партий и сохраняет `PAUSED` без выдачи новых;
паузу тоже можно продолжить. Отдельная отмена с подтверждением завершает запуск
без возможности продолжения и освобождает создание нового анализа сразу;
обычный MD выдаёт три таблицы частот и веса с затуханием по повторениям у одной
компании, а также таблицу названий вакансий с частотами и весом, но без цитат и текстов. По адресу
`/market-analysis?debug=1` появляется кнопка подробного проверочного MD с полными
текстами вакансий и диагностикой. Процент покрытия и сравнение с резюме не выполняются;
пользователь прикладывает актуальное резюме к промпту для внешнего агента отдельно.

На странице вакансий оценка отправляет только ещё не оценённые вакансии. Список содержит длину
сохранённого текста, но не сам текст: он добавляется на backend при оценке, если доступен.
Frontend отправляет один запуск в `POST /api/v1/vacancies/relevance/parallel` и опрашивает
общий прогресс. Backend делит работу на партии до 10 вакансий и до 30 000 символов
сохранённых описаний, по одному virtual thread на партию без лимита параллельности.
Процессы CLI в Generation Agent запускаются по бюджету памяти; часть партий может
ожидать в его очереди, сохраняя единый прогресс запуска на backend.
Общий настраиваемый предел агента по умолчанию — 4 одновременные пачки оценки и анализа рынка.
Одна длинная вакансия идёт отдельной партией без обрезки; без текста используются данные карточки.
Результаты партий сохраняются по мере завершения. После перезагрузки страницы активный запуск
восстанавливается через `/parallel/active`; прогресс считается как `evaluatedBefore + evaluatedCount`
из снимка запуска, поэтому сохранённые партии не учитываются повторно. Повторный запуск
отправляет только оставшиеся вакансии без оценки. Mock-режим сохраняет прежнее поведение.

Backend остаётся источником истины. Локальное состояние страницы хранит ввод, выбранную
строку, открытый dialog и кеш деталей на время жизни страницы, но не создаёт второй
долгоживущий доменный store. Общая загрузка простых страниц использует `usePageData`;
сложные экраны могут управлять конкурентными запросами сами.

Краткая сводка запуска содержит рассчитанное backend примерное оставшееся время. Экран
откликов обновляет его вместе с историей: во время работы показывает текущую оценку, а на
паузе — замороженную длительность после продолжения.

Форма запуска откликов содержит холостой режим. В нём сохраняются
максимум вакансий и случайная пауза между ними, но скрыты настройки писем и дневной лимит
откликов. Общий `AppCheckbox` используется для этого режима, AI-письма и выбора в таблице.
Mock-ветка создаёт демонстрационный завершённый запуск. API-ветка передаёт `mode: DRY_RUN`:
Browser Agent открывает деталки и сохраняет тексты без отправки откликов и генерации писем.
Статусы вакансий, очередь и дневной лимит откликов не меняются. Обычный режим передаёт `APPLY`;
старые запуски без поля режима считаются реальными откликами.
Исключение для архивной деталки: текст не сохраняется, элемент запуска показывается как
«В архиве», вакансия получает статус `CLOSED` и убирается из очереди. `CLOSED` нельзя
снова добавить к отклику ни поштучно, ни массово.

Анализ рынка принимает прогресс независимо от порядка завершения партий. `STOPPING`
означает ожидание всех уже выданных партий; новые backend не выдаёт. API и формат
готового отчёта прежние, число обработанных вакансий приходит из общего checkpoint.

## Mock-режим

`npm.cmd run dev` использует mock-режим, `npm.cmd run dev:api` — backend API. Production
всегда выбирает API независимо от переменной окружения. Сценарий мока задаётся
`?scenario=...` или `VITE_MOCK_SCENARIO` и валидируется в `runtime.ts`.

Mock-ветка воспроизводит те же ограничения и переходы, что и API, насколько они нужны UI.
При изменении контракта нельзя обновить только реальную ветку: моковые типы, данные и
действия также должны остаться валидными.

## Проверка

```powershell
npm.cmd run type-check
npm.cmd run build
node --test tests/*.test.mjs
```

Визуальное изменение дополнительно проверяется в mock- и API-режимах на длинных названиях,
пустых состояниях, ошибках и состоянии загрузки.
