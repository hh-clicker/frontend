# Уведомления

В API-режиме настройки сохраняются в PostgreSQL через `GET/PUT /api/v1/settings`.
Миграция backend `013-notification-settings` создаёт одну общую запись для всех аккаунтов,
`019-relevance-notifications` добавляет настройку завершения оценки вакансий,
а `035-market-notifications` — отдельную настройку завершения анализа рынка.
Разрешение на системные уведомления остаётся локальным разрешением браузера, не настройкой БД.

Корневой компонент опрашивает `/api/v1/settings/notification-state` каждые 5 секунд,
независимо от открытой страницы и выбранного резюме. Снимок содержит краткую сводку
последних 100 запусков; тексты писем и полная история вакансий не загружаются.

События: завершение запуска откликов или холостой загрузки текстов, автоматическая остановка, новые открытые задачи
внимания, завершение либо ошибка оценки релевантности вакансий, а также завершение
либо ошибка анализа рынка. Анализ рынка при первом появлении в снимке запоминается
без уведомления, чтобы после обновления приложения не переигрывать старые результаты.
Пауза анализа не вызывает системное уведомление. Завершение и ошибка анализа рынка
имеют отдельный переключатель; общие переключатели системных уведомлений и звука
по-прежнему определяют способ доставки.
Для холостого запуска сообщение о завершении показывает число загруженных текстов и ошибок загрузки.
Оно использует те же переключатели завершения и паузы, что и обычный запуск.
Ручная пауза и отмена не создают уведомление. Совпавшие завершение/остановка и задача
внимания объединяются в одно сообщение, если соответствующее событие включено.
Первый успешный снимок — тихая исходная точка. Последующие состояния сохраняются в
localStorage, в том числе при выключенных уведомлениях. Перезагрузка и включение
события не повторяют уже просмотренные состояния. Потеря соединения не стирает
исходную точку. Это отслеживание текущего состояния, не гарантированная доставка
каждого промежуточного перехода, произошедшего между опросами.
Несколько обновившихся запусков за один опрос объединяются в одну сводку и один звук.

Web Locks сериализует опрос и доставку между вкладками одного браузерного профиля.
Без Web Locks опрашивает только окно в фокусе. Разные браузеры/профили независимы.
При недоступном localStorage автоматическая доставка отключается, чтобы не повторять
события. Ошибка показа не повторяется бесконечно и не влияет на очередь откликов.

Системные уведомления требуют разрешения и защищённого контекста (HTTPS/localhost).
Звук синтезируется локально через Web Audio, без скачивания аудио. Для разблокировки
звука нужно взаимодействие с вкладкой; кнопка проверки также активирует звук.
Вкладка должна оставаться открытой. Сон компьютера, заморозка вкладки, запрет
автовоспроизведения и настройки ОС могут задерживать или подавлять доставку.
Клик по уведомлению открывает запуск либо список вакансий с правильными аккаунтом и резюме.

Mock-режим сохраняет демонстрационную страницу без реальных звуков и уведомлений.

## Telegram-бот

На странице `/settings` можно подключить собственного бота, созданного через BotFather. Frontend передаёт токен
backend один раз и больше его не получает. Backend проверяет бота, создаёт одноразовую ссылку со сроком 15 минут и
привязывает только личный чат после команды `/start`. Бот с настроенным webhook не подключается, поскольку webhook и
long polling нельзя использовать одновременно. Состояние подключения читается через `GET /api/v1/settings/telegram`,
подключение выполняется через `POST .../connect`, тест — через `POST .../test`, отключение — через `DELETE`.

При старте очереди backend создаёт одно сообщение со статусом запуска и обновляет его по мере обработки вакансий.
Для холостого запуска в нём показывается прогресс загрузки текстов, а итог не называется отправкой откликов.
Для выполняющегося запуска доступна кнопка паузы, для приостановленного — продолжения. Обе команды проходят через тот
же прикладной gateway, что и web-интерфейс, поэтому сохраняют все проверки состояния. Для каждой задачи внимания бот
создаёт отдельное сообщение с доступными в web действиями «Готово» и «В пропущенные». Ссылки на HH не отправляются:
анкеты, капча и авторизация остаются в управляемом профиле Browser Agent.

После завершения или отмены запуска бот создаёт отдельное итоговое сообщение. Пока остаются открытые задачи внимания
или уже начатая операция ещё не получила результат, подтвердить итог нельзя. После разбора всех ситуаций кнопка
«Подтвердить» удаляет промежуточный статус и сообщения задач, оставляя в чате итоговую статистику без кнопок.

Для анализа рынка бот создаёт одно сообщение при работающем анализе и редактирует
в нём счётчик обработанных вакансий и паузу. При ошибке, отмене или завершении
прогресс заменяется новым итоговым сообщением, чтобы событие пришло с уведомлением.
Старые завершённые
анализы после подключения/обновления не отправляются повторно. Telegram-сообщение
не зависит от переключателей системных уведомлений браузера; отдельные кнопки
управления анализом в боте пока не предусмотрены.

## Проверка без отправки откликов

- На `/settings` изменить параметры, сохранить, перезагрузить: значения сохраняются.
- Выдать разрешение по кнопке; проверить запрещённое разрешение и отсутствие поддержки.
- Проверить звук отдельно, уведомление отдельно и оба способа; проверить всё выключенное.
- Открыть две вкладки: одно изменение состояния должно дать одно сообщение.
- На существующих запусках проверить переходы/внимание через тестовые данные, не отправляя реальные отклики.
- Проверить переход по уведомлению другого резюме и отсутствие дубля после перезагрузки.
- Запустить оценку, уйти с вакансий и проверить уведомление и актуальный список после возврата.
- После недоступности backend восстановить соединение: старые сообщения не повторяются.
- Проверить Telegram-сообщение активного запуска, паузу и продолжение, обработку отдельной задачи внимания и финальное
  подтверждение с очисткой промежуточных сообщений.

Автотесты чистой логики: `node --test tests/notification-events.test.mjs` (Node 24+).
Backend: `NotificationSettingsTests`, плюс существующие архитектурные проверки.
