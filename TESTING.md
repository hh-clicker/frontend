# Режимы разработки и проверки frontend

## Проверки

```powershell
npm.cmd ci
npm.cmd run type-check
npm.cmd run build
node --test tests/*.test.mjs
```

## Моки

```powershell
npm.cmd run dev
```

Откройте адрес, который напечатает Vite. Моковые сервисы работают с синтетическими
данными в браузере, не отправляя отклики или запросы к настоящему HH/Codex/backend.
Сценарий задаётся query-параметром scenario, затем VITE_MOCK_SCENARIO, по умолчанию full.
Неизвестное имя также даёт full. Пример: /vacancies?scenario=empty.

| Значение | Состояние |
|---|---|
| full | Обычные полные демонстрационные данные |
| partial | Частично заполненные списки; генератор требует авторизации |
| empty | Пустые данные |
| agent-offline | Недоступные Browser Agent и генератор |
| error | Недоступный генератор |
| scanning | Поиск в процессе сканирования |
| selected | Вакансии, выбранные в очередь откликов |
| mixed | Обычный срез; в диагностике селекторов — все доступные проверки пройдены |

## Диагностика селекторов в моках

После `npm.cmd run dev` откройте `/browser?scenario=full` и нажмите
«Полная диагностика». В демонстрационном отчёте профиль и поиск сломаны, зависимые шаги
заблокированы. Кнопки «Исправить с ИИ» имитируют задержку и последовательное исправление
без запросов к HH, Codex или backend. Повторная полная диагностика сохраняет результат;
перезагрузка страницы сбрасывает демонстрационные исправления.

`scenario=partial` показывает исправленные первые три шага и поломку вакансии,
`scenario=mixed` — полностью пройденную диагностику с непроверенными состояниями форм,
`scenario=error` — недоступный Generation Agent, `scenario=partial` также требует входа в Codex:
диагностика работает, кнопки ИИ скрыты и показано объяснение. Выбор открытой вкладки работает на
синтетическом списке из четырёх страниц. Открывать демонстрационный
браузер вручную не требуется: «Выбрать вкладку» и «Полная диагностика» при необходимости
открывают его для выбранного аккаунта. Уже открытые вкладки при выборе не перезагружаются.

Эти сценарии доступны только в mock-сборке; `debugSelectors=1` сам по себе не переключает
production на моки. В `full` на страницах поисков и запусков также показаны синтетические
предупреждения со ссылкой на точечную диагностику. Переход должен показать тип страницы,
проблемные поля и кнопку проверки проблемной вкладки без автоматического запуска проверки.

Для обновления текста резюме откройте `/resumes` и нажмите «Обновить текст с HH» у выбранного
резюме. В mock-режиме обновляются синтетический текст и дата загрузки, настройки остаются
прежними. В API-режиме при сломанных селекторах печатной страницы старый текст остаётся,
а ошибка предлагает точечную диагностику RESUME; после починки обновление нужно повторить.

## Настоящий API

```powershell
npm.cmd run dev:api
```

Это интерфейс к реальному backend с обычными пользовательскими действиями.
Production всегда использует API: scenario не переключает установленное приложение на моки.
Проверяйте визуальные изменения на длинных названиях, пустых данных, загрузке и ошибках.

## Проверочный отчёт рынка

Query debug=1 на /market-analysis показывает дополнительную кнопку выгрузки подробного MD.
GET /api/v1/market-analyses/<id>/report?debug=true строит его из сохранённого снимка.
Модель повторно не вызывается. Файл содержит исходные тексты вакансий и цитаты.

Холостой запуск в диалоге откликов — реальная загрузка страниц HH без отправки отклика,
а не mock-режим. Диагностика backend и benchmark описаны в
[backend/TESTING.md](https://github.com/hh-clicker/backend/blob/master/TESTING.md).
